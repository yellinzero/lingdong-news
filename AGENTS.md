# 灵动新闻 · lingdong-news

Keep this app small. The desktop app uses Tauri 2 + vanilla TypeScript + Rust: `src/` for frontend, `src-tauri/` for native code, `tests/` for frontend and UI tests. One implementation serves macOS, Windows and Linux. Do not bundle a Node runtime or Chromium. It is a personal news ticker, not a trading system.

- Follow the system language for the app name: Chinese uses 灵动新闻, English and fallback languages use LingDongNews. Keep the bundle identifier, source IDs and storage/credential accounts independent of display names.

- Desktop development: `pnpm install --frozen-lockfile && pnpm tauri dev`. Validation: `pnpm test`, `pnpm test:ui`, `cargo test --manifest-path src-tauri/Cargo.toml`. Build: `pnpm tauri build`.
- RSS/Atom, standard JSON sites and local adapters must ALL emit the same versioned JSON envelope before consumption. Source-specific request/signing/parsing logic belongs in manifest.json + adapter.js packages under source-adapters/packages; all three preinstalled sources use the same QuickJS ABI as user-installed v2 packages. General RSS/JSON/mapping helpers live in Rust, never put provider-specific branches in Rust or the frontend. Legacy v1 mappings remain compatible. Repack preinstalled.json after editing example files; consistency tests enforce this.
- Channel lifecycle is shared by builtins and custom definitions: sources lists enabled channels; uninstalledSources excludes definitions from installation. Uninstall retains the local catalog, stable IDs, cached news and saved credentials so reinstall can reuse them. All-disabled/all-uninstalled is valid; drafts apply only on Save. V2 channel files embed complete manifest + script packages and may mix legacy configurations. Updates are explicit and lower versions are rejected. Execute only through the bounded QuickJS host API with exact declared network origins, no ambient file/process access, and host-only credential injection. Syntax inspection must not run the adapter.
- Source adapters normalize to the versioned feed contract in docs/integrations.md. Source tags are neutral metadata, distinct from keyword/AI hit labels. Never infer importance from provider flags.
- AI batches use shared policy, strict per-ID results, bounded concurrency and reservations before dispatch. Exact semantic duplicates reuse persisted judgments; near-duplicate variants with new content are separately judged. Keep pending jobs across raw-cache eviction, reject missing/duplicate/unknown IDs, ignore stale results, and never silently drop failed jobs.
- AI planning, content fingerprints and judgement application run in a Worker; networking is asynchronous in Rust. Default AI control is continuous pacing with native request/input rate limits and concurrency, never a mandatory daily news allowance. Daily caps are explicitly opt-in and default off for old preferences too. Usage must be atomically reserved and persisted before HTTP, including manual tests, failures and cancellations. Rate waits retain jobs without counting as failures, automatically resume and replan latest-first; changing limits must not reset the news cutoff. Keep the long-running ledger bounded through conservative minute aggregation. Stop invalidates pending/result epochs and aborts in-flight HTTP; a stale settings save must never resume it. New-only and recency limits intentionally exclude expired work while preserving the full news stream; ordinary appearance/source saves must not retry failed AI jobs. Keep cached highlights visible while paused.
- Keys stay in a separate native credentials.json in the per-user app data directory (plaintext by user choice; Unix directory 0700/file 0600, Windows inherits user profile permissions); never send them back to the frontend. Keep endpoint redirects disabled and certificate verification enabled. No credentials in cache, logs, test fixtures or browser localStorage.
- News must update in every presentation. Expanded lists NEVER automatically scroll down through history. Default follow-latest returns to the top only for a new/corrected latest story, even while hovered; no timer may move an expanded list. Compact starts with the latest full text. Finish every current story in full before advancing, with trailing reading space. New arrivals update only the offscreen successor; preserve any successor already visible. Never crop an unread suffix to prioritize a refresh. Idle-to-new transitions preserve visible glyph positions. Advance without a backward jump. Disabling automatic latest preserves manual reading position/selection on refresh.
- Keyword and AI preferences annotate the complete chronological stream; never hide unmatched, pending or failed judgements. Highlight matching text in compact and expanded modes. Both switches are off by default. Source selection and explicit search can narrow the list.
- Compact playback records a content version as completed once its full text has been displayed, without waiting for its tail to leave the window. It skips completed versions and identical republished text across source IDs/timestamps by default, persists bounded history, keeps unfinished stories pending and replays corrections. When all news is complete, keep the last visible text still and wait; never enqueue an already played latest story as an automatic fallback. It never filters expanded lists or marks attention read. Manual paging can revisit completed stories. Clicking compact news must open its full text at the matching row with bounded DOM; the context menu provides ordinary latest view and explicit AI state/control without adding hover buttons. Compact is news-only: no cumulative counts, decorative status dots or separators. Hover/focus previous/next and arrow keys page manually; resume marquee after a short delay even while hovered. The entire news strip must drag, with a movement threshold so clicks still expand and controls remain clickable. Compact width and expanded dimensions are adjustable and separately persisted.

- Model URLs, model names and keys are user-provided. Never fall back to a different API host; never log keys or include them in news/preferences/exports.
- Preserve source IDs, publication times, full public news text, and source attribution. Keep cache size bounded.
- Do not commit `node_modules/`, `target/`, `web-dist/`, `dist/`, test reports, local caches or credentials.

- Saving ordinary preferences must not query/write system credentials, restart AI, or refetch all sources. Credential access is reserved for explicit activation/tests or edited credentials/accounts.
- macOS builds use ad-hoc signing by default. Never discover, select, use or export company signing identities for this personal project. A personal distribution identity requires the user's explicit identification and authorization; installed certificates do not imply consent. Never import signing identities into CI without explicit authorization. Do not access or migrate legacy system credential stores automatically; old keys remain there until the user removes them.

- Settings save/cancel must return to the originating compact/glance/feed mode. AI quick actions start a valid saved configuration directly, open settings only when configuration or credentials are missing, and disable with one click. Disabling persists aiEnabled=false, cancels native requests and queued jobs, and never reads credentials. Keep AI control generations across saves so stale preferences cannot undo a newer stop. Currently one saved AI account/protocol configuration is supported; do not imply a multi-profile selector.

- Closing AI disables dispatch only: retain and display current cached judgements without credentials. Persist positive and negative decisions separately from bounded news, migrate existing context fingerprints, and reuse across source IDs/restarts even outside dispatch recency. Keep history bounded to 10,000 records/4 MiB in the Worker; apply concurrent patches without overwriting newer records.
- AI request cadence uses the user-configured rolling requestWindowMinutes (default 1) and legacy maxRequestsPerMinute count within that window. Smooth arrival count/length using a time-decayed model whose horizon follows that window. Never count repeated planning as new arrivals. Greedily combine ready work, allow a bounded two-second coalescing wait, and preflight the exact serialized native request against character caps; no token estimate. Native pacing, rolling-window counts, per-minute input and opt-in daily caps remain hard bounds.

- Public docs are minimal and action-first in both languages: one or two short sentences per README feature, matching configuration/result images, no progress notes or unrelated implementation commentary. Document core features; keep technical contracts, limits and commands in their guides. All feature screenshots use dark theme with orange accents.
